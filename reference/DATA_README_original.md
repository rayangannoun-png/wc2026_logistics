# Location Data

This folder contains the first location dataset skeleton for the FIFA World Cup
26 venue-branding logistics model.

## Tables

- `nodes.csv`: master list of all physical or proxy locations.
- `ports.csv`: ocean gateway attributes and current report rate assumptions.
- `depots.csv`: seven proxy depot/control nodes used for routing and storage.
- `storage_scenarios.csv`: low/base/high storage cost assumptions in USD per
  cubic metre per day.
- `stadiums.csv`: all 16 World Cup 26 host venues.
- `production_sites.csv`: The Look Company, Wasserman Live, and China-origin
  production candidates.
- `edges.csv`: candidate transport links between production sites, ports,
  depots, and stadiums.
- `node_sources.csv`: source/evidence notes for important node claims.
- `inventory_template.csv`: suggested inventory columns showing how inventory
  rows should reference location IDs.

## Modeling Notes

Depot locations are proxy nodes, not confirmed FIFA warehouse addresses. The
strongest location evidence is for Dallas/Arlington and Mexico City; other depot
nodes are justified by supplier/logistics footprint, host geography, and major
freight-market logic.

Depot storage cost is handled through scenarios rather than hard-coded in
`depots.csv`:

```text
storage_cost = volume_m3 * storage_days * storage_cost_per_m3_day_usd
```

Use `storage_scenarios.csv` for sensitivity testing:

- `low`: storage mostly bundled or cheap short-term warehousing
- `base`: handled commercial warehouse proxy
- `high`: secured/constrained event storage

Truck routes should normally start/end at `candidate_depot` nodes. Direct flows
from ports or production sites to stadiums can be allowed later as special edges
for nearby, pre-kitted, oversized, or time-critical shipments.

## Inventory Handoff

Inventory rows should reference `node_id` values from `nodes.csv`, because
`edges.csv` is built on `origin_node_id` and `destination_node_id`.

For depot references, use the depot's `node_id` such as:

```text
LAX_DEPOT_NODE
DFW_DEPOT_NODE
MEX_DEPOT_NODE
```

Do not use the shorter `depot_id` values from `depots.csv` in routing columns
unless the model explicitly joins `depots.csv` first.

## Edge Building

`edges.csv` is generated by:

```bash
python3 scripts/build_location_edges.py
```

By default, road distances use a fallback approximation:

```text
road_distance_km = haversine_distance_km * 1.25
```

Rows generated this way are marked:

```text
distance_method = fallback_haversine_x1.25
```

For routed road distances, set an OpenRouteService API key and rerun:

```bash
export OPENROUTESERVICE_API_KEY=...
python3 scripts/build_location_edges.py
```

When the API is available, road rows are marked:

```text
distance_method = openrouteservice_matrix_driving_hgv
```

The builder uses OpenRouteService's Matrix API with the heavy-goods-vehicle
profile (`driving-hgv`). If an API batch fails, only that batch falls back to
the haversine approximation.
